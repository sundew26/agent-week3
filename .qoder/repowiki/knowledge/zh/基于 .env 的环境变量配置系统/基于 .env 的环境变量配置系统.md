## 1. 使用的方案

后端（Python/FastAPI）与前端（Vite/Vue）各自通过 `.env` 文件加载运行时配置，未引入集中式配置中心或 YAML/JSON 配置文件。

- 后端：使用 `python-dotenv` 的 `load_dotenv()` 在模块导入时自动加载根目录下的 `.env` 文件，再通过 `os.getenv` 读取环境变量。
- 前端：通过 Vite 的 `VITE_` 前缀约定注入构建期常量，由 `vite.config.ts` 中的代理和端口等构建期配置管理开发环境行为。

## 2. 关键文件

- `backend/app/config.py`：后端唯一配置入口，调用 `load_dotenv()` 并暴露三个全局常量。
- `backend/.env.example`：提供后端所需的环境变量模板（`OPENAI_API_KEY`、`OPENAI_BASE_URL`、`LLM_MODEL`）。
- `frontend/.env.example`：提供前端所需的 `VITE_API_BASE_URL` 模板。
- `frontend/vite.config.ts`：定义开发服务器端口（`1993`）、反向代理目标（`http://localhost:1994`）以及路径别名 `@` → `src`。
- `backend/app/main.py`：FastAPI 应用启动处，硬编码 CORS 白名单（`http://localhost:5173`、`http://localhost:3000`），不依赖外部配置。
- `frontend/src/env.d.ts`：声明 Vite 客户端类型，使 `import.meta.env` 可用。

## 3. 架构与约定

### 后端配置加载流程
1. 任意模块导入 `app.config` 时，`load_dotenv()` 从工作区根目录加载 `.env`。
2. 通过 `os.getenv(key, default)` 读取键值，并提供默认值：
   - `OPENAI_API_KEY`：默认空字符串（必填项，无默认值）。
   - `OPENAI_BASE_URL`：默认 `https://api.openai.com/v1`。
   - `LLM_MODEL`：默认 `gpt-4o-mini`。
3. 这些常量以模块级全局变量的形式被其他模块（如 `graph.py`、`tools.py`）直接 import 使用，没有封装成配置对象或类。

### 前端配置方式
- 构建期常量：Vite 自动将 `VITE_*` 前缀的环境变量注入到 `import.meta.env`，前端通过该接口访问 API 基地址。
- 开发期代理：`vite.config.ts` 中 `/api` 请求被代理到 `http://localhost:1994`（后端默认端口），避免跨域问题。
- 端口约定：前端 dev server 固定为 `1993`，后端 FastAPI 默认 `8000`（但代理目标指向 `1994`，实际部署需调整）。

### 配置分层
当前仓库**没有实现多层配置覆盖**（如 dev/prod 多份 env、命令行参数覆盖、环境变量覆盖 .env）。所有配置均为单一来源：`.env` 文件 + 代码内默认值。

## 4. 约定与约束

- **后端必须提供 `.env`**：`OPENAI_API_KEY` 无默认值，缺失会导致 LLM 调用失败；建议通过 `.env.example` 提示用户复制并填写。
- **环境变量命名**：后端使用全大写蛇形命名（`OPENAI_API_KEY`、`OPENAI_BASE_URL`、`LLM_MODEL`），前端使用 `VITE_` 前缀加全大写（`VITE_API_BASE_URL`），遵循 Vite 约定。
- **CORS 白名单硬编码**：`main.py` 中将允许的来源写死为 `http://localhost:5173` 和 `http://localhost:3000`，未从配置读取，修改前端端口时需同步更新此处。
- **开发代理目标固定**：`vite.config.ts` 中代理目标 `http://localhost:1994` 与后端默认端口 `8000` 不一致，说明本地运行时需要显式指定后端端口或修改代理目标。
- **无敏感信息校验**：`config.py` 仅做字符串读取，未对 `OPENAI_API_KEY` 进行格式校验或长度检查。
- **无配置热重载**：`.env` 变更不会触发服务重启，需要重启后端进程才能生效。

## 5. 总结

该项目的配置系统极为轻量：后端用 `python-dotenv` + `os.getenv` 读入 LLM 相关密钥与模型设置，前端用 Vite 的 `VITE_` 前缀注入 API 地址。两者均缺乏环境隔离（dev/staging/prod）、配置验证和集中管理能力，适合小型开发项目，但在生产环境中需要补充配置校验、多环境管理和敏感信息保护机制。
